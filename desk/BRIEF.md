# Daji desk: shared brief for every builder

Project: Daji Cricket Ground (dajicricket.com). Server: Node 22 + TypeScript run directly (`node --experimental-strip-types`), SQLite via node:sqlite, no npm install at runtime, no framework. Admin front end: the NEW React + TypeScript desk in `desk/`, which must match **Prince Estate** (the reference app) in layout, design and code style.

## Page pattern (every page, no exceptions)
`<div className="stack">` then `<PageHead eyebrow title lede>` with the main action as a child (top right), then pill `Tabs` if there are sections, then `Stat` cards / `Table` / `Chip` status chips. Money is integer paise shown with `inr()`. Dates `fmtDate`. Times are epoch ms, India time (`fmtDateTime`). Use the classes already in `desk/styles.css` (card, card-head, card-pad, grid g2/g3/g4, row, stack, tbl, seg, btn / btn primary / btn ghost / btn sm, inp, badge b-good/b-warn/b-bad/b-info/b-gold/b-mute, muted, small, gold, hint, err, empty, form-grid, modal). Forms use `Field` + `<input className="inp">`, dialogs use `Modal`. Loading: `<Loading />`. Errors: `<ErrorBox>`. Toasts: `useToast()`. No emoji. Gold is an accent, not a fill. Must work at phone width (tables scroll in `.tbl-wrap`).

## Desk code
- `desk/src/lib.ts` (API client `api/post/put/patch/del/sendFile/download`, `useApi`, formatters, `can`), `desk/src/ui.tsx` (Icon, Logo, PageHead, Stat, Table, Tabs, Chip/Status, Field, Modal, Confirm, Empty, Loading, ErrorBox, useToast, useForm), `desk/src/App.tsx` (`useSession()` gives `me`, `ownerId`). `desk/src/registry.ts` already lists every page route. **Do not edit shared files**: `lib.ts, ui.tsx, App.tsx, registry.ts, main.tsx, styles.css, build.mjs, charts.tsx`. If you need a shared helper or style, put it in your own file: components in `desk/src/parts/<area>/*.tsx`, CSS in `desk/styles/<area>.css` (the build appends every file in styles/). Your page files are named in your task; each exports `default function Name({ sub }: { sub: string })` where `sub` is the rest of the path (e.g. `/bills/bil_1` gives sub `bil_1`).
- Sign-in is a bearer token the API client already sends. A super admin picks the business; owner-scoped endpoints (`/api/accounting`, `/api/tasks`, `/api/staff`, `/api/books`, `/api/media`, `/api/ask`, `/api/desk`) get `?ownerId=` added automatically. New owner-scoped APIs should live under `/api/accounting/...` or `/api/desk/...` for that reason, and server code must call `ownerOrFail(c, '...')` (see `server/src/routes/books.ts`).

## Server rules
- TypeScript run by Node's type stripping: **erasable syntax only** (no enums, namespaces, parameter properties). Imports end in `.ts`. Use `registerSchema('<unique-id>', sql)` for new tables (one column per line, plain types, soft delete columns `deleted_at/deleted_by`, `created_at/created_by/updated_at/updated_by`, ids from `newId('prefix')`, money in paise integers, times in epoch ms via `now()`, dates `YYYY-MM-DD` IST). Validate with `Validator` from `server/src/input.ts`, audit with `audit()`, errors with `HttpError`. Look at `server/src/accounting/books.ts` + `server/src/routes/books.ts` as the model of how a module is written.
- Permissions: do NOT add new permissions (the shared list in `shared/src/types.ts` is fixed). Use these: bookings/memberships `manage_bookings`; payments `verify_payments`/`record_payments`; accounting and bills `manage_accounting` (read: `view_reports`); tournaments/matches `manage_matches`; broadcasts and reminders `send_broadcasts`; payroll and staff pay: owner or super_admin only. Owners and super admins pass every permission check.
- Your route file is already created and wired into `server/src/app.ts` as an empty function (e.g. `server/src/routes/bills.ts`); fill it in. Do not edit `app.ts`.
- Add tests in `server/test/<area>.test.ts` using `server/test/helpers.ts` (see `books.test.ts`). Run only your tests: `cd server && node --disable-warning=ExperimentalWarning --test test/<area>.test.ts`. Also run `test/books.test.ts` and `test/accounting.test.ts` if you touched accounting.
